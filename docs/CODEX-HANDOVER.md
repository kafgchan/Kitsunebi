# 🦊 Kitsunebi Mod - Codex向けGUI・アセット引き継ぎ資料 (v0.4)

本書は、**Codex（GUI描画・テクスチャ・3Dモデル担当）** と **Antigravity（ロジック・Menu・ネットワーク・能力担当）** の円滑な協業のための仕様引き継ぎ書です。

## 1. 役割分担と競合防止ルール

| 担当区分 | 担当領域 / 専有ファイル | 留意事項 |
| :--- | :--- | :--- |
| **Codex 専有** | ・`KitsunebiAltarScreen.java`（祭壇GUI画面描画・操作）<br>・新規テクスチャPNG（防具、ツール、祭壇アトラス）<br>・3DモデルJSON（狐耳、狐尾、防具レイヤー、祭壇） | ロジック修正への介入は行わず、既存ファイルを一括再生成するスクリプト等は実行しない。 |

## 2. 狐火の祭壇GUI 仕様

### 2.1 画面基本設計
- **基本解像度**: `312 × 236` GUIピクセル（最小ウィンドウ `320 × 240` に完全収容）
- **テーマカラー**: 祭壇に合わせた紫系のグラデーションパネル、金色のアクセント境界
- **構成要素**:
  1. 上部：カテゴリ切替タブ（狐火 / 幻影ブロック / 装備・ツール）
  2. 左側：材料投入スロット（横3列 × 縦5行 = 15スロット）
  3. 中央上：選択アイテム一覧（アイコングリッド）
  4. 中央下：数量指定（プリセットボタン 1, 2, 4, 8, 16, 32, 64 および 1刻みスライダー）
  5. 右上：完成品プレビュー・取出しスロット
  6. 右中：必要素材一覧（投入数 / 必要数）
  7. 右下：「製作する / 修理する」実行ボタン
  8. 最下部：プレイヤーインベントリ（27スロット + ホットバー9スロット）

### 2.3 サーバー同期データ (`ContainerData` / `data`)

`KitsunebiAltarMenu` 内の `data` (長さ 3) により、以下の状態がクライアント・サーバー間で同期されます。

- **`data.get(0)`: カテゴリIndex (`0` 〜 `2`)**
  - `0`: 狐火（狐火7色 + 建築用狐火ブロック）
  - `1`: 幻影ブロック（フル、ハーフ、階段、スロープ、壁、柵、扉、感圧板、レバー、ボタン）
  - `2`: 装備・ツール・修理（防具4種 + ツール5種 + 神器修理）
- **`data.get(1)`: 選択Index (`selectionIndex`)**
  - 各カテゴリ内の選択中アイテム番号（0から開始）
- **`data.get(2)`: 製作数量 (`quantity`)**
  - 完成品の希望個数（`1` 〜 `64`）
  - **※カテゴリ2（装備・ツール・修理）選択時は常に `1` に固定**され、数量UIは非表示/無効化されます。

---

### 2.4 ボタンID仕様（`clickMenuButton(player, id)`）

`KitsunebiAltarScreen` からサーバーへ送信するボタンID体系は以下の通りです。

| 送信ID (`id`) | 動作 | 条件・備考 |
| :--- | :--- | :--- |
| `0` | カテゴリを「狐火」に変更 | 選択Indexは0にリセット |
| `1` | カテゴリを「幻影ブロック」に変更 | 選択Indexは0にリセット |
| `2` | カテゴリを「装備・ツール」に変更 | 選択Indexは0、数量は1に固定 |
| `100 + index` | 選択アイテムを変更 | `0 <= index < getSelectionCount()` |
| `1001` 〜 `1064` | 製作数量を変更（1〜64） | `id = 1000 + 数量`（カテゴリ2時は無効） |
| `2000` (`CRAFT_BUTTON`) | **「製作する / 修理する」を実行** | 素材消費・成果物出力処理を一括コミット |

## 3. レビュー指摘への対応状況

Codexのレビュー文書（`docs/V03-REVIEW.md`）で指摘された問題は、Antigravity側で以下の通り対処完了しています。

1. **[P1] 同期値が画面に反映されない問題**:
   - `KitsunebiAltarMenu` は内部フィールドではなく `ContainerData` を直接参照するよう完全改修。
   - カテゴリ変更時は `getSelectionCount()` に応じてボタン配列を安全に再構築可能。
2. **[P1] 部分取り出しによる素材全消費バグ**:
   - 右上の成果物枠（スロット15）はレシピプレビューではなく、**実在庫スロット（`output`）** に変更。
   - 「製作する」ボタン（ID: 2000）を押した瞬間にのみ、サーバー側でアトミックに素材を消費して成果物枠に格納されます。プレイヤーが右クリックで半分取ったりShiftクリックで部分移動しても、追加で素材が請求されることは一切ありません。
3. **[P1] 6スロットで64個製作の材料が入らない問題**:
   - 投入スロットを **15スロット（3列×5行）** に拡張。狐火64個（竹4スタック、ラピス2スタック、染料1、発光材1、アメジスト1）や建材64個も余裕をもって格納可能です。
4. **[P2] 扉上半分破壊時の回収不能バグ**:
   - `PhantomDoorBlock.java` において、UPPER / LOWER のどちらが破壊されても1回だけドロップ判定が実行されるよう修正済み。
5. **[P2] ライセンス表記不一致**:
   - `fabric.mod.json`, `README.md`, `LICENSE` をすべて `LGPL-3.0-or-later`（アセットは `CC BY 4.0`）に整合済み。

## 4. Codexへの提供メソッド一覧 (`KitsunebiAltarMenu`)

`KitsunebiAltarScreen` から呼び出し可能な主要メソッド：

```java
public int getCategoryIndex();            // 0: 狐火, 1: 幻影, 2: 装備・ツール
public int getSelectionIndex();           // 選択中インデックス
public int getQuantity();                 // 数量 (1〜64, 装備時は1)
public int getSelectionCount();           // 現在のカテゴリの選択肢総数 (8, 17, 10)
public boolean isEquipment();             // カテゴリ2判定
public ItemStack getSelectionStack(int index); // アイコン描画用ItemStack
public AltarCraftingEngine.RecipeResult getCurrentResult(); // 同期済みの計算結果
public AltarCraftingEngine.RecipeResult getCurrentResult(int previewQuantity); // スライダー操作中のローカルプレビュー用計算
public boolean canCraft();                // 現在製作可能か
public boolean canCraft(int previewQuantity);
```

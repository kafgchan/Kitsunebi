# 狐火の祭壇GUI — v0.3対応

Notionのv0.3追補（2026-10-18更新）と今回のGUI実装依頼に基づく変更。

## 操作

1. 左の横3列×縦5行、15スロットへ材料を投入。並べ方は不問。
2. 上のカテゴリから「狐火」「幻影ブロック」「装備・ツール」を選ぶ。狐火ブロックは「狐火」内の8番目に格納する。
3. アイコンから狐火の色、または幻影建材の形状・サイズを選ぶ。名前は表示とツールチップで確認できる。幻影建材に色選択はない。
4. 1・2・4・8・16・32・64のプリセット、または1個刻みのスライダーで**完成個数**を指定する。
5. 必要素材の投入済み数／必要数を全項目確認し、「製作する」を押す。
6. 製作済みアイテムを右上の取出し欄から受け取る。

「装備・ツール」は次の仕様用の仮カテゴリ。5つの仮枠を表示し、製作は無効にする。完成個数のボタン・ラベル・スライダーは表示せず、数量はサーバー側でも1に固定する。この変更で新規装備やレシピは追加しない。

素材不足または取出し欄の容量不足では製作しない。材料はサーバー上で再検証し、製作確定時に一度だけ消費する。部分取り出し・Shiftクリックでは追加消費しない。画面を閉じる際は投入材料と製作済みアイテムを返却する。

## 描画・同期

- 312×236 GUIピクセル。最小の320×240画面に収まる。
- 祭壇に合わせた紫系のパネルと金色のアクセント。背景はコード描画、アイコンは登録済みのアイテムモデルを使用する。
- 選択・完成品プレビュー・必要素材・数量・インベントリの領域を分離。
- 選択した完成品の長い名称は省略表示と全文ツールチップを併用。材料名は省略せず折り返して表示する。
- 発光材料は「グロウストーンダスト／輝くイカスミ」、代替材料は「スライムブロック／ハチミツブロック」「ソウルサンド／ソウルソイル」。バニラアイテム自身の翻訳名を使用する。
- 染料の表示は7色の選択に応じて対応する染料の正式名へ変更する。
- 選択状態は同期対象のContainerDataを直接参照し、カテゴリの同期後にボタンを再構築する。
- 6言語にUI文言を追加。
- スライダーは連続したマウス座標でつまみを描画し、完成個数だけを整数に丸める。操作中のプレビュー・素材数は即時更新する。数量はドラッグ終了時に送信し、応答前の古い同期値でつまみを戻さない。プリセット・左右キーは即時送信し、左右キーは1個ずつ変更する。

## 検証

- 両ローダーのビルドと既存形状テスト。
- NeoForge専用クライアントで実際のGUIクラスを320×240で3カテゴリ描画。日本語の画面をスクリーンショット確認。テスト用クライアントはワールドを開かず自動終了する。
- NeoForge専用サーバーで実際のMenu/Slot/vanillaクリック処理を検証：全7プリセット、狐火64個の材料容量、ContainerData更新、横縦混合ハーフ、材料不足・出力満杯、右クリック半分取り出し、部分Shiftクリック、不正な選択／数量ID、遠距離操作拒否。15枠目のShift移動、狐火ブロックのカテゴリ内移動とレシピの対応、装備・ツールの数量変更／製作拒否も検証する。
- `:neoforge:runAltarVerifyClient` で画面確認、`:neoforge:runSlopeVerifyServer` で実メニュー・既存ブロック挙動の回帰確認。通常起動時には検証処理を実行しない。
- 実GUIの追加検証：全7色の染料名、代替素材の両方の正式名、257箇所のドラッグ座標と古い同期値、数量確定後の応答待ち、左右キーの1個刻み。

実サーバーに複数クライアントを接続した遅延・同時操作テスト、Fabricでの実画面撮影は未実施。

## 今回変更していない事項

レシピの材料・比率、データ駆動化、JEI/EMI連携は今回のGUI改修で変更していない。任意個数の端数コストは既存エンジンの切り上げ方式を維持する。Notionで未確定の端数方針や柵・レバーの加工材料については、従来のレビュー指摘が残る。v0.3全体の未確定事項を確定したという意味ではない。
